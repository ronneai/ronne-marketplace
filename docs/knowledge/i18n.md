# Languages: how the web app's text is kept

The web app speaks English (the source), Brazilian Portuguese (`pt`) and Canadian French (`fr`)
([feature 129](../features/129-languages-foundation/SPEC.md)). Only the platform's own labels are
translated: item content, what people write, `rmk`, the MCP server and the API stay as authored.
Read this before writing any text a person reads on a screen.

## Where text lives

- **`apps/web/messages/<locale>/<namespace>.json`**, one file per area (`common`, `shell`, …), the
  same keys in all three languages. English is the source: write it first, then the other two.
  A new namespace adds its three files and a line in `src/i18n/namespaces.ts` (also its type).
- **ICU messages** for anything with a number or a name: `{count, number}`, `{count, plural, one {…}
  other {…}}`, `{role, select, …}`. Whole sentences with placeholders, never fragments that are
  joined in code. Plural categories differ by language; `other` is always required.
- **In components:** `const t = useTranslations("shell")` then `t("nav.home")` (a non-async server
  component or a client component), or `await getTranslations("shell")` in an async server
  component. Keys are typed from the English files: a wrong key fails `pnpm typecheck`.
- **In tests:** components render in English (`src/test/intl-setup.ts` reads the real files). A
  test of another language wraps the render: `inLocale("pt", () => renderToStaticMarkup(…))`.
- **Never** write text into JSX or a `title`/`label`/`placeholder`/`aria-label`/`alt`/
  `description`/`summary`/`heading`/`tooltip` attribute in a folder the lint rule covers (the
  `overrides` entry in `biome.json` that loads `i18n-raw-jsx-*.grit`). A string that isn't
  translated text (a brand name, a protocol) carries `// biome-ignore lint/plugin: <why>`. A folder
  joins the list when its screens are moved over; text the rule can't see (default parameters,
  template strings, objects) is on the author and the reviewer.

## Errors

- **An action that returns a code** (`{ error: "wrong_password" }`): the component turns the code
  into words with a key in its own messages (`account.password.errors.wrong_password`). The code
  stays the contract; the words are the screen's.
- **A domain error with a message** (`TokenLimitError`, 152 more): the action returns
  `await errorText(error)` (`src/i18n/errors.ts`). It looks up `errors.<ClassName>` in the
  `errors` namespace with the error's own fields as the message's values (`{limit}`,
  `{tokenName}`), and falls back to the error's English message, so a new error is never blank,
  only English until someone translates it. The API keeps giving the English message and its code.
  A sweep adds the errors its screens can show, in all three languages; a test per error class
  checks the three texts (`src/i18n/errors.test.ts`).

## Checks that keep it true

- `src/i18n/messages.parity.test.ts`: every key of English in `pt` and `fr`, no extra key, the same
  ICU placeholders, valid ICU.
- At run time a missing message shows English (and is logged once); CI fails on it.
- The lint rule above, tested on fixtures in `src/i18n/raw-text.test.ts`.

## Gotchas

- After adding a **new namespace** (a message file registered in `src/i18n/namespaces.ts`), Vitest can
  fail every test with `Unknown variable dynamic import: ../../messages/en/<file>.json`: its cache
  holds the old file list. Delete the caches (`node_modules/.vite*` and `node_modules/.vitest-cache`,
  at the root and in `apps/web`, whichever exist) and run again. A new key in an existing file is
  fine.
- Timestamps keep one numeric form in every language (`2026-10-20 21:58 GMT-4`, 049); only numbers
  (`12,345` / `12.345` / `12 345`) follow the language.
- E2E: a test that needs several languages signs in once and opens the same session with
  `browser.newContext({ locale, storageState })`, with a user of its own (the sign-in limit,
  [e2e-sign-in-limit.md](./e2e-sign-in-limit.md)).

## Typography

- **Portuguese (Brazil):** no space before `: ; ? !`.
- **French (Canada):** a space before `: ; ? !` (a regular space for now), the curly apostrophe `’`
  (`s’ouvre`, `Journal d’audit`), « guillemets » for quotes.
- Both: no gendered address of the person; "you" as `você` / `vous`.
